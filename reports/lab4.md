# 第六章 第七章 练习

## 实现功能

### 迁移 sys_spawn

改从文件系统读取`elf`文件，并在构建`TCB`时多构建一个`fd`表。

### 实现 sys_fstat

为了提供`Stat`的`nlink`信息，我在`DiskInode`中添加一个`nlink`字段表示该`Inode`被硬链接过多少次。（新建一个文件相当于被链接了1次）在每次硬链接或取消硬链接的时候动态维护这个`nlink`的值。

注意因为多添加了一个字段，所以需要把`INODE_DIRECT_COUNT`减去1，确保`DiskInode`仍然占用$128$B，为一个块的$\frac{1}{4}$大小

`Stat`中的其他字段实验代码均已提供相似接口

### 实现 sys_linkat

首先判断是否会有链接同名文件等等错误，然后给`root_inode`这个目录下新建了一个`DirEntry`，这个`DirEntry`的`inode_id`与被链接的文件的`inode_id`一样。

最后将`DiskInode`中的`nlink`字段进行加1。

### 实现 sys_unlinkat

首先判断文件是否存在，然后将`DiskInode`中的`nlink`字段进行减1。接着在`root_inode`这个目录下把对应的`DirEntry`置空，确保之后不能被找到。

注意到如果`nlink`字段变成了0，就说明这个`inode`已经无法被访问到了。需要对它所占有的数据块进行清除，然后释放掉`inode`块。

## 简答问题

### ch6

#### 简答1

`root inode`用于索引其他所有的文件。

- 如果`size`损坏，会导致计算这个目录下的文件个数有误。
- 如果`nlink`损坏，会导致硬链接数目出错。
- 如果`type_`损坏，在做遍历文件、查找文件的过程中会因为它不是目录而崩溃。
- 如果`direct` `indirect1` `indirect2`损坏，会导致它能索引到的`DirEntry`出现错误，进而找不到真正的文件。

### ch7

#### 简答1

比如在2025s-rcore-GSteve-Paul目录下，执行
```bash
find . -name '*.rs' | xargs cat | wc -l
```
就可以知道这个项目里的Rust源文件总共有多少行

#### 简答2

可以在内核中开辟一段内存，用管程机制对它进行管理，并允许其他进程利用管程机制提供的接口对其内容进行读写访问。
